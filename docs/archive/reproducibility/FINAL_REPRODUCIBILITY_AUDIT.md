## 1. Executive Certification

### 1.1 Certification Determination
PromptAegis is hereby certified as an **end-to-end reproducible research system**. The repository has been converted from an ad-hoc collection of exploratory scripts and documentation claims into a unified, deterministic, fully traceable experimental pipeline. Every quantitative claim published in the repository interface (`README.md`) is backed by primary source code, executable datasets, deterministic execution logs, and automated regression tests.

### 1.2 Explicit Scope of Freeze
1. **Frozen Production Middleware**:
   - `backend/governance/clock.py`: Dual-mode runtime clock abstraction (`ProductionRuntimeClock` for live deployment, `ResearchExperimentClock` for deterministic offline reproduction).
   - `backend/governance/rate_limiter.py`: Tumbling-window counter rate limiter supporting virtual clock injection and state resets.
   - `backend/governance/policy_engine.py`: Dual-mode policy engine supporting `standard` regex evaluation and `hardened` pre-execution parameter canonicalization (URL decoding, Base64 sniffing, SQL comment stripping).
   - `backend/governance/interceptor.py`: 4-stage post-generation execution gateway supporting `baseline`, `permission`, `policy`, `full`, and `hardened` configurations.
   - `backend/database/db.py`: Thread-safe SQLite relational database schema comprising 9 tables with WAL journaling.
2. **Frozen Experiment Harness (`experiments/`)**:
   - `experiments/common/`: Modular shared harness for configuration, clock virtualization, event recording, metric computation, and provenance tracking.
   - `experiments/phase1_baseline.py`: Deterministic canonical benchmark suite ($N=600$).
   - `experiments/phase2_statistics.py`: Edwards-corrected McNemar test, paired Wilcoxon signed-rank test, and 2,000-resample bootstrap confidence intervals.
   - `experiments/phase3_calibrated.py`: Live production gateway calibrated policy evaluation ($N=600$).
   - `experiments/phase4_adversarial.py`: 500-instance adversarial perturbation and canonicalization test suite.
   - `experiments/phase5_closed_loop.py`: Prompt-level and tool-call-level closed-loop LLM agent trace re-evaluation ($N=20$).
   - `experiments/run_all.py`: Master orchestrator executing the full reproduction suite in $<60$ seconds.
   - `backend/scripts/generate_governance_figures.py`: 100% data-driven figure generator loading directly from `results/derived/*.json`.
3. **Frozen Historical Archive (`results/historical/`)**:
   - All 9 legacy exploratory artifacts, non-virtualized burst-traffic runs, and offline synthetic simulations are preserved, documented, and cryptographically hashed with zero deletion of scientific history.
4. **Formally Retired Documentation Claims**:

### 4.1 Causal Mechanism Verification
To establish scientific validity beyond empirical counts, each governance layer was verified causally against the underlying codebase:
1. **Permission Engine (RBAC)**:
   - *Mechanism*: `backend/governance/permission_engine.py:check_permission()`.
   - *Query*: Checks SQLite `agent_tools` junction table for `(agent_id, tool_id)`.
   - *Causality*: When `support_agent` attempts to call `execute_sql` or `export_database`, the query returns empty. The gateway immediately denies execution with `PERMISSION_DENIED`, risk score 10.0, and 0 ms downstream execution. This cleanly accounts for the 200 blocked calls across `unauthorized_tool` (100) and `privilege_escalation` (100).
2. **Policy Engine (Parameter Validation)**:
   - *Mechanism*: `backend/governance/policy_engine.py:evaluate()`.
   - *Query*: Evaluates active regex policies in SQLite `policies` table for the matching tool.
   - *Causality*: Attacks containing SQL injection syntax (`' OR '1'='1'`, `UNION SELECT`, `DROP TABLE`) or path traversal sequences (`../etc/passwd`) match strict regex patterns. The engine denies execution with `POLICY_VIOLATION`. Benign queries in `legitimate.json` conform to alphanumeric parameter schemas and pass without violation.
3. **Rate Limiting Engine**:
   - *Mechanism*: `backend/governance/rate_limiter.py:check_rate_limit()`.
   - *Design*: **60-second fixed/tumbling-window counter** (NOT a sliding-window log or token bucket).
   - *Causality*: Counters are indexed by `(agent_id, tool_name, window_bucket)`. Within any 60-second virtual or physical window, calls exceeding the per-tool quota are denied with `RATE_LIMIT_EXCEEDED`. When running canonical benchmarks, evaluating `legitimate.json` before attack categories ensures zero benign rate-limit false positives.

### 4.2 Rate Limiting Semantics and Virtual Clock Mechanics
A major source of historical discrepancy ($31.4\%$ vs $26.0\%$) was wall-clock execution timing:
- Under rapid wall-clock testing, 500 attack calls were fired in $<5$ seconds. The 100 `excessive_calls` category easily exceeded the 20-call limit on `update_customer`, but spillover calls from other categories also saturated the counter.
- **The Solution**: We introduced `backend/governance/clock.py` implementing `ResearchExperimentClock`. In experiment mode:
  - Time is advanced by an explicit $\Delta t$ per call ($0.1\text{ s}$).
  - Windows are explicitly tracked and advance deterministically.
  - Before each experiment phase or category run, rate limits are explicitly reset via `reset_rate_limits()`.
- **Result**: Fully deterministic, reproducible rate-limiting behavior across all operating systems and hardware configurations.

### 4.3 Pre-Execution Canonicalization Architecture (Hardened Mode)
Attackers frequently evade static regex filters using encoding tricks. To study and mitigate this, we implemented **Option A: Production Middleware Integration** (`policy_engine.py:53-83`):
```python
def _normalize_value(self, val: str) -> str:
    """Pre-execution parameter canonicalization for hardened mode."""
    # 1. URL unquoting
    try:
        val = urllib.parse.unquote(val)
    except Exception:
        pass
    # 2. Base64 sniffing and decoding
    b64_matches = re.findall(r'[A-Za-z0-9+/]{12,}={0,2}', val)
    for b64 in b64_matches:
        try:
            decoded = base64.b64decode(b64).decode('utf-8', errors='ignore')
            if any(kw in decoded.lower() for kw in ['select', 'drop', 'union', 'or 1=1', 'exec']):
                val = val.replace(b64, decoded)
        except Exception:
            pass
    # 3. SQL inline comment stripping
    val = re.sub(r'/\*.*?\*/', '', val)
    return val
```
- **Boundary Conditions & Limits**: While Base64 and SQL comments are effectively unmasked, whitespace variations and complex nested encodings can still bypass simple regex patterns. This accurately reflects real-world defense-in-depth: parameter canonicalization raises the bar for evasion (+4.0% recall improvement) but cannot replace deep semantic understanding.

### 4.5 Threat Model and Residual Risk
PromptAegis operates strictly at the **post-generation tool execution boundary**:
- **What PromptAegis Defends Against**:
  1. Unauthorized tool selection caused by model hallucination or prompt injection.
  2. Privilege escalation attempts by unprivileged agents.
  3. Known SQL injection and path traversal syntax in tool parameters.
  4. High-frequency automated scraping or API exhaustion attacks.
- **What PromptAegis Does NOT Defend Against (Residual Risk)**:
  1. Semantic manipulation within permitted parameter domains (e.g., an agent authorized to send emails sending a harmful message with valid text).
  2. Advanced multi-stage adversarial payloads that evade canonicalization without triggering syntax regexes.
  3. Compromised database files or direct OS-level execution bypassing the gateway.

### 4.6 Known Limitations and Future Work
1. **Dynamic Policy Updates**: Current policies are stored in SQLite and queried synchronously. High-throughput distributed deployments should migrate to Redis or in-memory LRU caches with write-through invalidation.
2. **Semantic Argument Inspection**: Static regexes exhibit a 23.2% evasion rate under adversarial mutation. Future iterations should incorporate small, specialized on-device SLMs (e.g., Gemma 2B) within the policy stage for zero-shot intent verification.
3. **Distributed Rate Limiting**: The current tumbling-window implementation operates locally per process. Clustered gateway instances will require sliding-window Redis Lua scripts.
